# 404STARTUP — Agent Guide

## What this is
A library of playable, fully-offline 404 pages. Static site, ZERO dependencies,
zero build step. Hosted on Render (static site, publish dir ".", no build command).
Every push to main auto-deploys.

## Hard rules (never break)
1. ZERO DEPENDENCIES: no npm packages, no CDNs, no external fonts, no frameworks,
   no build tooling. Vanilla HTML/CSS/JS in plain files only.
2. 404.html is the site-wide OFFLINE fallback page. Its game script is INLINE and
   contains a 3-game switcher (dunes/orbit/terminal). Do NOT extract, refactor, or
   restructure it. Do NOT add library games to its switcher.
3. sw.js: cache const is n404-vN — bump N on EVERY commit that changes served
   files. Keep the PRECACHE list in sync when files are added/removed. Offline
   must always work for pages AND /assets/ (assets are cache-first).
4. Game pages live in library/<dir>/<dir>.html (single game via
   N404.mount('<id>'), NO switcher) and library/<dir>/<dir>_page.html
   (description page with animated SVG hero + PLAY button linking to
   <dir>.html). Generated by assets/build_library.sh — prefer regenerating via
   that script over hand-editing generated files.
5. assets/n404-core.js is MINIFIED. The readable source is in git history:
   `git log --oneline -- assets/n404-core.js` then
   `git show <hash>:assets/n404-core.js > assets/n404-core.js`.
   To change engine code: restore source, edit, re-minify with
   `terser assets/n404-core.js -c -m -o tmp && mv tmp assets/n404-core.js`,
   and PRESERVE the /*! ... */ banner as line 1.
6. Legal: never remove the /*! 404STARTUP (c) 2025 Yosa-Shiawase */ banners in
   assets/*.js, the LICENSE file, or the foxConsole script in index.html.
7. Every HTML file must end with </html>. After edits, verify with greps before
   committing.

## Adding a new game (exact checklist)
1. Restore engine source (rule 5), add Games.<id> IIFE + INFO.<id> entry,
   re-minify.
2. Add one entry to assets/library-manifest.js (id, dir, num, title, tag, short,
   long, feats).
3. Add an art entry to assets/game-art.js (animated SVG using classes a-run,
   a-spin, a-fall, a-flick, a-ping, a-grid, a-roll, a-pad, a-rise, a-bob).
4. Add a `dir|id|NAME|num` line to the PAIRS block in assets/build_library.sh.
5. Run `bash assets/build_library.sh` (regenerates all library pages AND sw.js
   PRECACHE list).
6. Confirm the sw cache version was bumped; if not, bump manually.
7. Commit with a clear message and push to main.

## Site map
- index.html — landing: hero, fixed canvas scroll-story backdrop (dino/fox),
  marquee, bento grid, custom-404 Instagram CTA (@yosashiawase), voices section
  (NIRAKSHAN placeholder), about, fox easter-egg hunt (3 foxes -> unlocks orbit
  theme, stored in localStorage n404_fox_set3 / n404_site_theme).
- dashboard.html — visitor's best scores from localStorage (keys n404_best_<id>
  and legacy nf404_best_<id>).
- library/index.html — full grid of all games.
- 404.html — offline fallback arcade, 3-game switcher, self-contained.
- sw.js — network-first for navigations, cache-first for /assets/, offline
  fallback to /404.html for unknown navigations.

## Verification habits
- After any change: `tail -c 20 <file>` on edited HTML (must show </html>).
- grep for feature markers (e.g. `grep -c storyBg index.html`).
- Mobile check: layout must survive 360px width; no horizontal scroll.
- Offline check: hard-refresh online once, then airplane mode, then reload a
  library game page — it must fully work from cache.
